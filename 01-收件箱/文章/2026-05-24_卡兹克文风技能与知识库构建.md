## 一、选题方法论：HKR 质检模型

**S 级选题 = 三项兼备**
- **热点性**（Hot）：是否蹭到了当前关注点？
- **关联性**（Related）：是否和你的人设/领域强相关？
- **锐度**（Keen）：是否有反常识、反主流的切入角度？

**及格选题至少占两项**，只占一项或零项 → 主动调整方向。

> **核心逻辑**：把主观判断变成可量化的筛选，问的不是"好不好"，而是"占了几项"。

## 二、协作哲学：AI 定位 = 「超级素材库 + 思维伙伴」

| 交给 AI 做 | 人必须自己做 |
|-----------|-------------|
| 找证据、找类比 | 第一手观察 |
| 补背景知识 | 核心创意角度 |
| 按角度扩写 | 情绪的真实表达 |
| 梳理逻辑结构 | 数据→人物的同理心转换 |

> **灵魂口诀**：AI 擅长「补全」，人必须提供「灵魂」。

## 三、内容原型：五种可复用叙事结构

| 原型 | 叙事重心 |
|------|---------|
| **产品体验型** | 先用感官故事破冰，再用产品逻辑收尾 |
| **热点复盘型** | 先给结论，再用事件时间线复盘 |
| **人物故事型** | 先给性格切片，再讲事件，再归因 |
| **方法论型** | 先讲问题痛点，再给方法论，再附案例 |
| **观点对冲型** | 先摆对立观点，再逐层拆解，最后给立场 |

> **使用规则**：动笔前先判断文章属于哪个原型，按对应模板重心写，不从零设计结构。

## 四、质量控制：四层自检金字塔

```
L1 事实核验  → 日期、数据、人名、引用来源是否正确？
L2 逻辑自洽  → 有没有自相矛盾？有没有跳跃性断言？
L3 表达清晰  → 有没有冗余词？有没有读者看不懂的黑话？
L4 像不像人  → 真的有人会这么说吗？有没有 AI 味？
```

> **关键区分**：L1-L3 可让 AI 自检，L4 必须人来判断。不能只靠规则检查"像不像真人写的"。

## 五、Skill 打磨方法（迭代公式）

1. 指定命题（用已发布文章的标题）
2. AI 按 skill 创作 → 自己对比原文章
3. 好的地方保留，不好的剔除
4. 迭代几篇，直到满意
5. **持续打磨** → Skill 同步进化

## 七、知识库构建方案（LLM Wiki 思路）

> 参考 Karpathy 的 [llm-wiki](https://github.com/karpathy/llm-wiki)，基于 Obsidian + Markdown 构建

**核心思路**：
- 原始文档统一 `raw/`
- AI 自动 ingest → 建立知识图谱
- 历史文章 = 写作素材库
- 新内容 = 知识库增量

**流转路径**：
```
原始素材 → raw/ → AI ingest → knowledge/  → 调用写作
     ↑                                    ↓
  剪藏/爬取                          skills/
                                  调用知识卡片
```
