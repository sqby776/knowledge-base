# RULEBOOK — 知识库使用与维护规则

> 这是 Ground Truth 层次的第二层。这份文件定义知识库的操作规则、矛盾处理、信任评判标准。
> 当知识库内容之间有冲突时，以本规则为准。

## 第一部分：知识消费规则（读取时）

### 规则 1：信任度裁决

当多条笔记对同一主题给出不同说法时：

```python
裁决优先级 = [
    ("status: active", "confidence: high",   "使用，不质疑"),
    ("status: active", "confidence: medium", "使用，注明来源时间"),
    ("status: needs-review", "confidence: medium", "使用但标注可能过时"),
    ("status: active", "confidence: low",    "交叉验证后使用"),
    ("status: needs-review", "confidence: low", "不信任，需人工确认"),
    ("status: superseded",  "*",              "不信任，查 superseded_by"),
    ("status: archived",    "*",              "不信任，仅作历史参考"),
]
```

### 规则 2：时间优先

**同置信度下，updated 日期越近的越可信。**

```python
# 两个笔记都说 active + high，但一个 updated 2026-05 一个 updated 2026-07
# → 取 2026-07 的
```

### 规则 3：来源优先

**有来源链接的笔记 > 无来源的笔记 > 模型推理的结论。**

```python
# 笔记有 sources: [01-收件箱/xxx.md] → 可信
# 笔记无 sources → 可作为参考，但需标注
# 模型自己推理的 → 需在知识库中找到佐证
```

### 规则 4：矛盾标记

发现两条 active+high 笔记互相矛盾时：

1. 不假设哪条正确
2. 在两条笔记中都添加 `contradiction: [[另一条笔记]]` 标记
3. 在 `07-地图/` 下创建矛盾记录笔记
4. 报告给 [船长] 请求裁决

## 第二部分：知识维护规则（写入时）

### 规则 5：新笔记准入标准

一条信息值得写成笔记，当且仅当：

- ✅ 是**可复用的知识**（不是一次性的操作记录）
- ✅ 是**经过验证的**（不是猜测或假设）
- ✅ 有**明确的适用边界**（知道什么时候用、什么时候不用）
- ❌ 不是"今天做了什么"的日志（那是 log.md 的事）
- ❌ 不是工具文档的复制粘贴（那是收件箱的事）

### 规则 6：置信度赋值规则

| trust_score | 含义 | 条件 |
|:-----------:|------|------|
| 1.0 | 绝对确定 | 作者写的代码/亲手验证的结论 |
| 0.9 | 非常确定 | 官方文档引用的、多个独立来源一致的 |
| 0.8 | 确定 | 单一权威来源的、经过一次验证的 |
| 0.7 | 较确定 | 经验总结、推理可靠的 |
| 0.6 | 一般 | 有来源但未验证的 |
| 0.5 | 不确定 | 收件箱原文、未经验证的信息 |
| 0.3 | 低可信 | 30天未更新的笔记 |
| 0.1 | 不可信 | 90天未更新的笔记 |
| 0.0 | 废弃 | 已被 superseded_by 取代 |

### 规则 7：自动衰减

笔记的 trust_score 随未更新时间自动衰减：

```
30天未更新 → trust_score × 0.8
60天未更新 → trust_score × 0.5
90天未更新 → trust_score × 0.2
120天未更新 → 自动标记 status: archived
```

**例外**：`00-系统/SOUL.md`、`00-系统/RULEBOOK.md`、`知识库架构.md` 不衰减。

### 规则 8：矛盾解决流程

发现矛盾时：

1. 在 `07-地图/矛盾记录.md` 中记录
2. 两条笔记各加 `contradiction_with: [[对方]]` 标记
3. 降低双方置信度至 0.5
4. 报告给 [船长] 裁决
5. 裁决后：胜出方恢复置信度，败方标记 `status: superseded` + `superseded_by: [[胜出方]]`

### 规则 9：收件箱归档规则

收件箱（`01-收件箱/` 和 `01_inbox/`）中的原始资料：

- 只追加不修改
- 归档后不可删除（保留 provenance）
- 笔记必须通过 `sources` 字段引用来源

### 规则 10：结晶摘要规则

每次工作会话结束时，如果产出了可复用的知识：

1. 在 `07-地图/` 下写结晶摘要
2. 摘要中链接新创建的笔记
3. 摘要中记录未解决的问题
4. 摘要中记录"下次可以做的改进"

## 第三部分：规则执行

### 规则 11：规则本身可修改

本规则可以由 [船长] 随时修改。改完后在 log.md 中记录变更。

### 规则 12：规则冲突处理

当 [[SOUL]] 和 [[RULEBOOK]] 冲突时，以 [[SOUL]] 为准（身份原则 > 操作规则）。
