# Skill 迭代打磨法

> 来源：《数字生命卡兹克文风复刻 skill 深度拆解》
> 核心：以 Skill 的方式沉淀经验技巧，就是为了同步进化，越用越好用。

---

## 迭代公式

```
第 N 轮：命题 → AI 按 Skill 创作 → 你对比满意文章 → 好保留，坏剔除
                                    ↓
                              更新 Skill
                                    ↓
                            第 N+1 轮循环
```

---

## 五步迭代流程

### Step 1：选定命题

从**你已发布的文章标题**中选一个，不要凭空想。

> 原因：已发布文章 = 你已经"及格"的参照系，有明确的满意度基准。

### Step 2：AI 按 Skill 创作

用当前版本的 Skill 让 AI 写一篇新文章（同命题），不要提示 AI 参考你原文章。

> 原因：你是在测 Skill 本身的能力，不是在帮 AI 抄作业。

### Step 3：逐段对比

把你满意的原文章和新文章并排对比，逐段分析：

| 原文章 | AI 产出 | 判断 |
|--------|---------|------|
| 哪个部分 AI 写得更好？ | 哪个部分原文章更好？ | 记录差异点 |
| 原文章的节奏/语气 | AI 的节奏/语气 | 列出不同点 |

### Step 4：更新 Skill

根据对比结果，**具体地**更新 Skill：

| 发现 | Skill 更新动作 |
|------|--------------|
| AI 开头不够吸引人 | 在 Skill 的"开头模板"加一条规则 |
| AI 情绪平淡 | 在 Skill 的"语气规范"加情绪强度要求 |
| AI 逻辑跳跃 | 在 Skill 的"结构检查"加逻辑连接词清单 |
| AI 结尾太突兀 | 在 Skill 的"结尾规则"加收尾要求 |

### Step 5：重复

继续 Step 1，直到你对 Skill 产出的满意率稳定在 80% 以上。

---

## 迭代原则

### ✅ 要做

- **每次只改 1-2 个点**：不要一次性大改 Skill，改多了不知道哪个有效
- **改完马上测**：更新 Skill 后立刻跑一轮验证
- **记录改了什么**：在 Skill 里加更新日志（修改日期 + 改了什么）
- **尊重你自己**：如果 AI 写出了比你好的句子，写入 Skill

### ❌ 不要做

- **不要追求完美主义**：1.0 版本差不多就能用，迭代才是关键
- **不要一次改十几条规则**：效果不可追溯
- **不要因为一篇失败就推翻 Skill**：样本太少，可能只是命题本身难
- **不要把 Skill 当成固定答案**：它是活的，持续更新

## 版本管理

每个 Skill 用 Semantic Version 标记：

```
v1.0.0 → 初始版本（直接改造别人的 Skill）
v1.1.0 → 第一轮迭代（基于第一篇对比）
v1.2.0 → 第二轮迭代（基于前三篇对比）
v2.0.0 → 有底气用这个 Skill 独立写了
```

每次更新在 Skill 末尾加：

```markdown
---
## 迭代日志
- v1.1.0 (2026-05-24)：新增"开头模板"规则，修正语气偏平淡问题
- v1.0.0 (2026-05-xx)：初始版本，基于卡兹克 Skill 改造
---
```

## 关键感悟

> "配置整个流程并不难，一个晚上就跑通了。但需要长期投入时间打磨的，是属于你自己的 Skill。"

**AI 辅助创作的真正价值**：它不帮你做决定，它帮你把那些不需要做决定的事情快速处理掉，然后让你有时间，去做只有你能做的事情。
