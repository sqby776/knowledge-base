## 1. 核心概念与机制

Darwin-Skill 将模型训练中的"自主实验循环"（类似 Karpathy 的 `autoresearch`）应用于 Skill 优化。它把 Skill 改进当作一项有严格工程纪律的科学过程。

### 4 步优化循环

1. **AI 自动修改：** 一个 Agent 修改 SKILL.md 文件
2. **8 维评分：** 另一个 Agent 用加权评分系统评估新版本
3. **棘轮机制（Git Commit）：** 如果分数提高，保留变更（git commit）
4. **回滚（Git Revert）：** 如果分数下降，回滚到之前版本（git revert）

> **核心价值：** "你可以自由实验，失败了也不损害现有版本。"

### 5 条工程原则（从 38 次手动迭代中总结）

1. **单一变量原则：** 每次只修改一个 SKILL.md，同时改多个 Skill 无法归因
2. **审计独立：** 修改 Skill 的 Agent 不能是评分的 Agent（类比安然/安达信丑闻；记账人和审计人必须是不同实体）
3. **棘轮机制：** 分数只能升不能降，分数下降则回滚
4. **双重评估：** 结构（写得对不对）+ 性能（实际好不好用）
5. **人在回路（Human-in-the-Loop）：** 每次优化后暂停，展示 diff、评分变化、测试输出对比，用户确认后继续

## 2. 8 维评分系统（满分 100 分）

分数分为 **结构分（60 分）** 和 **效果分（40 分）**。

### A. 结构维度（静态分析）— 60 分

| 维度 | 权重 | 评估标准 |
|------|:----:|----------|
| 前置元数据质量 | 8 | 名称标准、描述含触发词、≤1024 字符 |
| 工作流清晰度 | 15 | 步骤明确可执行、有编号、输入输出清晰 |
| 边界条件处理 | 10 | 异常处理、回退路径、错误恢复 |
| 检查点设计 | 7 | 关键决策前有用户确认环节 |
| 指令具体性 | 15 | 含具体参数、格式、示例，可直接执行 |
| 资源整合 | 5 | 引用/脚本/资源路径可访问 |

### B. 效果维度（实时测试）— 40 分

| 维度 | 权重 | 评估标准 |
|------|:----:|----------|
| 整体架构 | 15 | 层级清晰、无冗余、无遗漏 |
| 实际效果 | **25** | **权重最高**。用真实测试提示词运行，对比有 Skill 和无 Skill 的输出质量 |

> **洞察：** 一个 Skill 可能有完美的结构但在实践中失败。反之，粗糙但有效的 Skill 比漂亮但无用的 Skill 更有价值。25 分的"实际效果"权重就是为了弥补这个问题。

## 3. 实战指南

### 步骤 1：安装

```bash
npx skills add alchaincyf/darwin-skill
```

**Fallback：** 如果 GitHub 连接差，下载 zip 解压到 `~/.workbuddy/skills/darwin-skill/`。

### 步骤 2：初始评估（只读）

```
评估所有skills的质量
```

扫描所有 Skill，设计测试提示词，运行基线分数，输出分数表。

### 样本分数表

| Skill | 分数 | 主要失分点 |
|-------|:----:|----------|
| steve-jobs-skill | 86 | — |
| content-creator | 84 | — |
| draft-writer | 82 | — |
| fact-checker | 82 | — |
| claude-code-info... | 78 | 边界条件偏弱 |
| cover-generator | 75 | 无 references 目录 |
| virality-predictor | 74 | 无 references 目录 |
| dbs | 73 | description 偏短 |
| diagram | 72 | 无用户确认检查点 |
| humanizer | 69 | 流程偏松散 |
| baoyu-imagine | 69 | 更像 CLI 手册 |
| skills-updater | 65 | 无触发词 + 无检查点 |
| yao-meta-skill | 58 | 无触发词 + 流程抽象 |
| find-skills | 56 | 全英文 + 无检查点 |
| any2pdf | 32 | 几乎为空 |

**如何阅读：**
- 总分：相同 Skill 不同 AI 模型的分数差异不大，说明评分有区分度
- 结构分 vs 效果分：结构分高的 Skill 效果不一定好
- 自建 Skill 平均 78 分 vs 社区 Skill 平均 60 分

### 步骤 3：启动优化

```
启动 Darwin-Skill 优化
```

Agent 自动运行"优化循环"。

## 4. 核心收获总结

| 核心概念 | 内容 |
|----------|------|
| 4 步优化循环 | AI 修改 → 8 维评分 → 棘轮保留 → 回滚 |
| 5 条工程原则 | 单一变量、审计独立、棘轮机制、双重评估、人在回路 |
| 8 维评分 | 结构 60 分（静态分析）+ 效果 40 分（实时测试） |
| 效果分权重最高 | 25 分（实际测试），弥补结构分与实际效果不匹配的问题 |
| 人在回路 | 每次优化暂停，用户确认后再继续 |

---

## 5. 对当前系统的价值

1. **可以对我们的 Skill 做自动评分**：用 8 维评分系统扫描现有 Skill，找出薄弱环节
2. **自动化优化流程**：无需手动迭代，AI Agent 自动修改 → 评分 → 保留/回滚
3. **持续改进**：每次修改都是可追溯的（Git 版本控制），失败可回滚
