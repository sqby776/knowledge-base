# MCP 集成：给 Hermes 接上整个互联网

> 来源：https://mp.weixin.qq.com/s/rmRbiXeRMyJxPUexfHWlsw

事情是这样的。去年我写过一篇文章，聊的是给 Hermes 部署一个舒适的开发环境。那篇文章的核心思路是把 Hermes 当成一个个人智能助理来用——帮我写代码、整理文档、管理知识库。但说实话，那时候的 Hermes 有一个很明显的短板：它没法直接跟外部世界交互。想查个数据库，得我手动导出 CSV 喂给它。想看个 GitHub Issue，得我先打开浏览器截图。想查天气，得我复制粘贴。怎么说呢，像个被关在别墅里的天才——脑子很好使，但出不去。这个局面在今年发生了根本性的变化。Hermes 从 v2.x 开始内置了 MCP 客户端支持。MCP 全称 Model Context Protocol，你可以把它理解成 AI 界的 USB-C 接口——一个统一的标准，让 AI 模型能直接调用外部工具和数据源。今天这篇文章，我就带你一步步把 Hermes 的 MCP 跑通。先感受一下在聊配置之前，我想先让你感受一下 MCP 上线之后的对话体验是什么样的。假设我现在配好了三个 MCP 服务器：GitHub Issues、SQLite 数据库和一个天气查询 API。那么我跟 Hermes 的对话会变成这样：我：帮我看看这个项目根目录下有哪些 Python 文件，然后查一下数据库里 orders 表的结构。Hermes: 好的。项目根目录下有&nbsp;app.py、models.py、config.py&nbsp;三个 Python 文件。orders 表的字段是：id (INTEGER)、user_id (INTEGER)、amount (FLOAT)、status (TEXT)、created_at (TEXT)。我：查一下上海今天的气温，然后对比一下上周同一天的数据。Hermes: 上海今天 25°C，多云。上周同一天是 28°C，晴。气温下降了 3 度，可能跟最近入秋有关。我：把 orders 表里 status 是 "pending" 的记录写成一份 Markdown 报告，保存到桌面上。Hermes: 查到了 3 条 pending 记录，报告已保存到&nbsp;~/Desktop/pending_orders_report.md。看到区别了吗？这些操作没有一个需要我手动切换窗口、复制粘贴、或者写 curl 命令。我就是在聊天界面里说人话，Hermes 自己去调用对应的工具把事情干了。这才是 MCP 最直观的感受：聊天即操作。MCP 配置文件的写法好，说正题。Hermes 的 MCP 配置写在&nbsp;~/.hermes/config.yaml&nbsp;里，在&nbsp;mcp_servers&nbsp;这个键下面。安装完 Hermes 后，默认的配置是这样：mcp_servers: {}大括号代表还没配任何服务器。接下来我们要往里面填内容。MCP 服务器有两种连接方式：第一种是 stdio 方式：Hermes 直接启动一个本地子进程，通过 stdin/stdout 通信。延迟低，适合装在本地的工具。写法：mcp_servers:&nbsp; github:&nbsp; &nbsp; command: "npx"&nbsp; &nbsp; args: ["-y", "@modelcontextprotocol/server-github"]&nbsp; &nbsp; env:&nbsp; &nbsp; &nbsp; GITHUB_TOKEN: "${GITHUB_TOKEN}"第二种是 HTTP 方式：连接一个远程的 MCP 服务器，适合云端部署的服务。写法：mcp_servers:&nbsp; weather:&nbsp; &nbsp; url: "https://weather-mcp.example.com/mcp"&nbsp; &nbsp; headers:&nbsp; &nbsp; &nbsp; Authorization: "Bearer your_api_key_here"几个重要的配置选项：字段作用适用场景command&nbsp;+&nbsp;args本地启动的可执行文件和参数stdio 服务器url远程 MCP 端点地址HTTP 服务器headersHTTP 请求头部（比如 API Key）HTTP 认证env传给 stdio 子进程的环境变量令牌/密码timeout工具调用超时，默认 120 秒慢接口tools.include只启用哪些工具（白名单）安全控制tools.exclude排除哪些工具（黑名单）安全控制enabled: false禁用此服务器但不删除配置临时关闭注意：配置里的&nbsp;${VAR}&nbsp;变量引用是从&nbsp;~/.hermes/.env&nbsp;文件里读取的。不要把 API Key 直接写进 config.yaml，放在&nbsp;.env&nbsp;里引用更安全。实操场景 1：连接 SQLite 数据库这个场景最实用。如果你手头有一个项目带着 SQLite 数据库，配好之后可以直接让 Hermes 帮你查数据。先装一个 SQLite MCP 服务器。Hermes 官方推荐用&nbsp;@anthropic/server-sqlite&nbsp;来做演示：配置：mcp_servers:&nbsp; sqlite:&nbsp; &nbsp; command: "npx"&nbsp; &nbsp; args: ["-y", "@anthropic/server-sqlite", "/Users/liuyadong/projects/myapp/data.db"]装好之后重启 Hermes。然后你就可以直接问了：我：查一下 users 表里有多少条记录，然后列出最近注册的 5 个用户。Hermes: users 表共有 127 条记录。最近注册的 5 个用户是：- 张三 (zhangsan@email.com) — 2026-05-28- 李四 (lisi@email.com) — 2026-05-27- 王五 (wangwu@email.com) — 2026-05-25- 赵六 (zhaoliu@email.com) — 2026-05-24- 钱七 (qianqi@email.com) — 2026-05-22我：看看这个项目的表结构，然后帮我分析一下有没有可以优化的索引。Hermes: 当前数据库有 5 张表。我注意到&nbsp;orders&nbsp;表的&nbsp;user_id&nbsp;字段没有索引，但你在查询中经常用它来 JOIN users 表，建议加一个索引。看到没有？原来你要做的事情是：打开终端 → 跑 sqlite3 → 写 SQL → 看结果 → 再写 SQL → 理解结构 → 自己分析。现在就是一句话的事。实操场景 2：连接天气查询 API光连本地数据库还不够，MCP 更大的价值在于接外部 API。我用一个开源 MCP 服务器&nbsp;mcp-server-weather&nbsp;来演示（基于 OpenWeatherMap 的 API）。配置：mcp_servers:&nbsp; weather:&nbsp; &nbsp; command: "npx"&nbsp; &nbsp; args: ["-y", "@nicholaschen/mcp-server-weather"]&nbsp; &nbsp; env:&nbsp; &nbsp; &nbsp; OPENWEATHERMAP_API_KEY: "${OPENWEATHERMAP_API_KEY}"API Key 放在&nbsp;~/.hermes/.env&nbsp;里：OPENWEATHERMAP_API_KEY=your_actual_key_here重启 Hermes，然后：我：北京今天天气怎么样？Hermes: 北京今天 27°C，晴转多云，湿度 45%，西北风 3-4 级。空气质量良。我：对比一下上海和深圳今天的气温和湿度。Hermes: 上海 25°C，湿度 70%；深圳 29°C，湿度 82%。深圳体感会更闷热一些。我：接下来三天杭州会下雨吗？Hermes: 杭州未来三天天气预报：周四多云 26°C，周五阵雨 23°C，周六小雨 21°C。周五和周六都有雨，建议带伞。我再强调一次，这些对话里我没有打开任何一个浏览器，没有访问任何一个网站。我就是坐在终端里打字聊天，Hermes 自己去调 API 把数据拿回来的。费用方面：MCP 服务器本身绝大多数都是开源的，不额外收费。但像 OpenWeatherMap 这种背后调用的 API 服务有各自的定价——OpenWeatherMap 的免费额度是每天 1000 次调用，对于个人使用完全够了。如果有更高的需求，付费套餐大约 40 元/月起。其他 API 服务也类似，搜个 API、查个 GitHub 这些场景通常在免费额度内就能覆盖。这个场景最有意思的地方在于，我每次说"帮我查一下天气"，Hermes 背后调的是实时 API，不是从某个训练数据里背出来的。这对于"信息比较旧"这个 AI 的经典痛点，是一种很直接的解决方式。实操场景 3：搭建自己的 MCP 服务器前面两个场景都是直接用社区现成的 MCP 服务器。但如果你想对接自己公司的内部 API，或者封装一个自定义工具，那就需要自己写一个 MCP 服务器了。好消息是，写一个 MCP 服务器比想象中简单。我手写一个最小的例子——一个能查本地时间的工具。用 Python，几十行代码就够了：from mcp.server import Server, stdio_serverfrom mcp.types import TextContent, Toolimport datetimefrom typing import Anyserver = Server("local-time")@server.list_tools()async def list_tools() -&gt;
