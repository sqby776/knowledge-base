# 报表看板分析与优化方案

> 基于现有系统代码分析 + 仪表盘UX设计最佳实践的综合评估

## 现有系统能力

### 看板 (`/dashboard/`) — ECharts 驱动
| 功能 | 状态 | 详情 |
|:----|:----:|:----|
| 10种图表类型 | ✅ | 综合/对比/趋势/占比/分布/排名/穿透/雷达/仪表/散点 |
| 三级下钻（院→科→人） | ✅ | 医院/科室/个人级分析 |
| 多时期对比 | ✅ | 支持选多个年月对比 |
| 6个统计指标卡 | ✅ | 员工数/应发/扣款/个税/实发/人均 |
| 环比同比 | ✅ | MoM + YoY 分析 |
| 科室/人员筛选 | ✅ | 分类→科室→人员三级 |
| 聚焦模式 | ✅ | 点击图表放大 |
| 导出Excel | ✅ | 看板数据导出 |
| **后端查询次数** | ⚠️ 48次 | 单次刷新执行约48次DB查询 |

### 报表中心 (`/report/`) — Chart.js + 表格
| 功能 | 状态 | 详情 |
|:----|:----:|:----|
| 7种子报表 | ✅ | 科室/个人/年度/季度/月度/对比/成本 |
| 图表展示 | ⚠️ 有限 | 仅`/report/center/`有饼图+柱图(Chart.js) |
| 表格展示 | ✅ | 各报表页以表格为主 |
| 筛选 | ✅ | 年月+科室+人员 |
| 导出Excel | ✅ | 分竖版/横版/A3 |
| 打印 | ✅ | 浏览器打印 |

## 诊断出的问题

### 🔴 P1: 性能 — 每次刷新48次DB查询
```python
# dashboard.py 单次 API 调用执行链：
SalaryResult.query.filter_by()           # 1 次  主查询
Employee.query.filter_by(status=1).all() # 2 次  员工映射
Department.query.filter_by(status=1)     # 3 次  科室映射
_get_trend_data() → 6次查询              # 9 次  近6月趋势
_get_dept_compare() → 每科室1次          # ~15次 科室对比
_get_composition()                       # 16次  构成
_get_distribution()                      # 17次  分布
_get_monthly_trend() → 12次查询           # 29次  全年月度
_get_employee_list()                     # 30次  员工列表
_get_ranking()                           # 31次  排名
_get_hospital_mom()                      # 32次  环比
_get_hospital_yoy()                      # 33次  同比
# 多时期模式下，每个时期重复上述流程...
```

**影响**：看板加载慢，特别是多科室、多时期时。

### 🟠 P2: 两套图表库不一致
```python
# dashboard.py 用 ECharts（echarts.min.js）
# report/center.py 用 Chart.js（chart.umd.min.js）
```

**影响**：
- 用户在看板和报表中心看到不同风格的图表
- 两套库增加了页面加载体积
- ECharts 功能更强但只用于看板，Chart.js 较弱却用于报表

### 🟠 P3: 全量加载 — 切换图表类型不按需查询
当前设计：`api_dashboard_data()` **一次性返回所有图表数据**，前端根据 `chart_type` 只显示对应图表。

**影响**：用户只看"趋势"时，后端也计算了分布、构成、排名等用不到的数据。

### 🟡 P4: 缺少图表交互功能
- ❌ 不能点击图表下钻（如点击饼图某块→显示该科室详情）
- ❌ 不能长图表导出PNG
- ❌ 图表之间无联动筛选

### 🟡 P5: 统计卡片缺少趋势指示
```
当前：  员工人数: 256
优化版：员工人数: 256  ↑3.2% (比上月)
```

### 🟢 P6: 数字格式不统一
- 统计卡片：`<div class="num">256</div>` — 无千分位
- 表格：`'%.2f'|format(r.earn_amount)` — 两位小数但无千分位
- 应加千分位：`25600` → `25,600.00`

### 🟢 P7: 报表中心表格可读性
- 科室汇总表：每科室一张卡片，明细行多时页面过长
- 缺少"只看合计"折叠模式
- 缺少搜索/过滤表内数据功能

## 优化方案（按优先级）

### 🔴 P1: 性能优化 — 查询次数减半

```python
# 优化1：批量预加载（取代循环内逐条查询）
# 当前：
for d in depts:
    d_total = sum(r.net for r in SalaryResult.query.filter_by(dept_id=d.id, year=y, month=m).all())
# 优化后：
sr_all = SalaryResult.query.filter_by(year=year, month=month).all()
dept_totals = defaultdict(float)
for r in sr_all:
    dept_totals[r.dept_id] += r.net_amount

# 优化2：按需加载（只查当前chart_type需要的数据）
# 当前：一次查所有图表数据
# 优化后：chart_type=trend 只查趋势数据
if chart_type == 'trend':
    result['trend'] = _get_trend_data(year, month)
elif chart_type == 'composition':
    result['composition'] = _get_composition(year, month, results)
# ... 其余数据暂不查询

# 优化3：6个月趋势改为一条SQL搞定
current = sum(r.net for r in SalaryResult.query.filter_by(year=y, month=m).all())
prev_months = db.session.query(
    SalaryResult.month,
    func.sum(SalaryResult.net_amount)
).filter(
    SalaryResult.year == year,
    SalaryResult.month.between(m - 5, m - 1)
).group_by(SalaryResult.month).all()
```

**预期效果**：48次 → 15-20次（按需加载模式可降到5-8次）。

### 🟠 P2: 统一图表库为 ECharts

```html
<!-- 报表中心：移除 Chart.js，改用 ECharts -->
<script src="{{ url_for('static', filename='js/echarts.min.js') }}"></script>
```

ECharts 优势：
- 看板已经在用，保持一致
- 支持更丰富的图表类型（树图、雷达、仪表盘）
- 内置下钻交互
- 导出为图片（`chartInstance.getDataURL()`）

### 🟠 P3: 按需加载API

```python
# 新增 chart_type 参数过滤
@app.route('/api/dashboard_data/')
def api_dashboard_data():
    chart_type = request.args.get('chart_type', 'overview')
    result = {'stats': get_stats(year, month, ...)}  # stats 始终返回
    
    # chart_type → 只查对应的数据
    LOAD_MAP = {
        'overview': ['trend', 'compare', 'composition', 'distribution'],
        'trend': ['trend', 'monthly_trend'],
        'compare': ['dept_compare'],
        'composition': ['composition'],
        'distribution': ['distribution'],
        'ranking': ['ranking'],
        'treemap': ['treemap'],
        'radar': ['dept_compare', 'composition'],
    }
```

### 🟡 P4: 图表下钻 + 联动

```javascript
// ECharts 点击事件 → 联动筛选
chartTrend.on('click', function(params) {
    // 点击趋势图的某个月份 → 自动切换到该月
    refreshDashboard({year: params.data.year, month: params.data.month});

chartCompare.on('click', function(params) {
    // 点击科室柱状图 → 下钻到该科室详情

});
```

function fmtNum(val) {

}
// 使用

## 实施优先级

| 优先级 | 优化项 | 工作量 | 影响 | 依赖 |
|:------:|:------|:-----:|:----|:-----|
| **P0** | 按需加载API（分chart_type查） | 小 | 大幅降低加载时间 | 无 |
| **P0** | 批量预加载替代循环查询 | 中 | 48→15次查询 | 无 |
| **P1** | 统计卡片千分位 | 小 | 提升可读性 | 无 |
| **P1** | 统计卡片+趋势箭头 | 小 | 一目了然 | P0按需加载 |
| **P2** | 统一图表库为ECharts | 中 | 一致体验 | 无 |
| **P2** | 图表点击下钻 | 中 | 交互升级 | P0按需加载 |
| **P3** | 报表表格折叠/搜索 | 中 | 提升浏览效率 | 无 |
