# 长期记忆管理方法论 — 从混沌到精准

> **编译时间**: 2026-06-05
> **来源**: 微信公众号

## 核心论点

长期记忆不在于"量"，而在于"精准"。记忆污染、上下文噪声会严重降低输出质量。

## 四类记忆污染

| 污染类型 | 表现 | 后果 |
|---------|------|------|
| 临时当永久 | 如"周五 review"被存为永久规则 | 后续对话过时上下文 |
| 非结构化碎片 | 分散的事实缺乏框架 | AI 难以有效利用 |
| 情绪噪声 | "这个模板太烂了"被存为约束 | 输出受情绪绑架 |
| 上下文过载 | 记忆过多增加 noise | AI 花更多精力过滤无关信息 |

## 高质量记忆标准

好记忆必须 **Short（短）、Stable（稳定）、Actionable（可执行）**。

## 三个关键模板

### 模板1：写入前过滤

```
请先判断这条信息是否适合写入长期记忆。
判断标准：
1. 一个月后它是否仍然有用？
2. 它是否会影响我以后反复做类似任务？
3. 它是长期偏好、项目规则、工作方式，还是只是临时信息？
4. 如果以后继续使用它，会不会误导你？
5. 它能不能压缩成一句清晰、稳定、不过期的记忆？
```

### 模板2：记忆清理

```
请帮我检查当前长期记忆是否有污染。
重点检查过期信息、一次性任务、临时路径、太长太散的记忆、重复表达、容易误导的记忆。
结果分三类：建议保留 / 建议压缩 / 建议删除。
```

### 模板3：结构化整理

```
请根据最近的对话，帮我整理一版适合写入长期记忆的内容。
只保留以后长期有用的信息，按结构输出：
1. 长期偏好
2. 固定工作方式
3. 当前项目的长期规则
4. 反复踩过的坑
5. 默认遵守的判断标准
```

## 五类核心记忆

| 类型 | 说明 | 影响范围 |
|------|------|---------|
| 长期偏好 | 沟通风格和交互偏好 | 决定每次回复 style |
| 固定工作方式 | SOP 和框架 | 决定输出 structure |
| 项目长期规则 | 特定项目的固定约束 | 防止 context drift |
| 重复教训 | 错误模式避免 | 经验缓冲区 |
| 决策标准 | 选择判断的标准框架 | 辅助判断 |
