# 工资管理系统

> 医院工资管理及报表导出 Web 应用，基于 Flask + SQLite/PostgreSQL。

## 项目信息

| 属性 | 值 |
|------|-----|
| 技术栈 | Python 3.11, Flask, SQLAlchemy, SQLite |
| 前端 | Jinja2, Bootstrap 5, 原生 JS (SPA 风格) |
| 导出 | openpyxl (Excel), WeasyPrint (PDF), 浏览器打印 |
| 路径 | `~/workspace/office/SalarySystem_Flask/` |
| 版本 | v1.0.0 (2026-07-12) |
| 端口 | 5000 (开发), 5001 (生产) |

## 功能模块

| 模块 | 路由 | 说明 |
|------|------|------|
| 科室管理 | `/department/` | CRUD + 排序 + 导入导出 |
| 员工管理 | `/employee/` | CRUD + 批量调薪/调科/导入导出 |
| 工资管理 | `/salary/` | 按模块查看工资表 |
| 工资分类 | `/table/center/` | 按分类查看工资表 |
| 报表中心 | `/report/` | 汇总/年度/月度/对比/成本 |
| 系统设置 | `/system/` | 参数/模块/用户/审核 |
| 数据管理 | `/data/` | 手动导入/备份恢复/归档 |

## 关键架构决策

### 双入口单工资表

`/salary/(模块)` 和 `/table/center/(分类)` 两个入口指向**同一套**工资表渲染函数。权限组 `salary:*` 和 `table:*` 互为镜像。

**为什么**：按"模块"管理和按"分类"管理各有操作员，两个入口共用数据但权限隔离。

### N+1 查询优化

最隐蔽 N+1 的来源是 `apply_threshold()` 函数——每次循环对每个员工额外做 3 次 DB 查询。

**修复**：在循环外预加载 `emp_map` + 阈值配置字典，传参给调用函数。

### eval → simple_eval 迁移

历史原因使用原生 `eval()` 执行公式，迁移到 `simple_eval()` 白名单引擎。**这是 P0 安全漏洞**。
