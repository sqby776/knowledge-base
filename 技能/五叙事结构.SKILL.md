# 五种可复用叙事原型

> 来源：《数字生命卡兹克文风复刻 skill 深度拆解》
> 核心逻辑：不是每次写作都从零设计结构，而是先判断内容属于哪个原型，按对应「模板重心」来写。

---

## 原型总览

| 原型 | 叙事重心 | 适用场景 |
|------|---------|---------|
| **产品体验型** | 感官故事 → 产品逻辑 | 产品评测、App 使用体验 |
| **热点复盘型** | 结论 → 时间线复盘 | 新闻事件、行业动态 |
| **人物故事型** | 性格切片 → 事件 → 归因 | 人物报道、创业者故事 |
| **方法论型** | 痛点 → 方法 → 案例 | 教程、经验分享、技能传授 |
| **观点对冲型** | 对立观点 → 逐层拆解 → 立场 | 争议话题、深度评论 |

---

## 原型一：产品体验型

### 结构
```
开篇感官故事（场景化描写） → 过渡到产品背景 → 核心功能拆解 → 体验评价 → 总结推荐
```

### 模板重心
- 第一个段落必须**有画面感**（开个具体的场景）
- 产品逻辑放在感官故事之后，不要一上来就堆参数
- 结尾给出**明确判断**：值得买/不值得买/适合谁

### 示例开头
"周三晚上 11 点，我把手机放在桌边充电，关了灯，打开 XXX App——然后整整 20 分钟没动过。"

---

## 原型二：热点复盘型

### 结构
```
标题给结论（悬念式） → 事件还原（客观时间线） → 深层原因分析 → 影响判断 → 趋势预判
```

### 模板重心
- 标题即结论，不要绕弯子
- 时间线只列关键节点，不流水账
- 深层原因分析是核心价值，不要停在对事件的描述

### 示例开头
"这件事，如果你只看官方公告，会完全看不懂。"

---

## 原型三：人物故事型

### 结构
```
标题给性格切片 → 切入一个关键事件 → 事件细节描写 → 人物内心的合理性 → 跳出事件做归因
```

### 模板重心
- 开篇不给传记，给**一个性格判断**
- 事件细节要具体，不要概括
- 归因部分才上升到观点层面

### 示例开头
"我发现，真正厉害的人都有一种能力：能在别人还没看见问题的时候，就已经开始害怕了。"

---

## 原型四：方法论型

### 结构
```
痛点共鸣（读者觉得"对，就是这个问题"） → 方法论框架 → 步骤拆解 → 案例佐证 → 可操作总结
```

### 模板重心
- 痛点要**精确到具体场景**，不要泛泛而谈
- 方法论要**可编号、可照搬**
- 案例要**真实**，不能编

### 示例开头
"90% 的人做 XX 的时候，第一步就走错了。"

---

## 原型五：观点对冲型

### 结构
```
标题摆出对立 → 先写主流观点 A → 再写反方观点 B → 逐层拆解 B 的问题 → 给出自己的立场 C
```

### 模板重心
- A 观点必须**足够有代表性**，不能是稻草人
- B 观点的拆解要**公正**，不能偷换概念
- 最终立场 C 是文章的价值，不能缺席

### 示例开头
"所有人都说 XX 是对的，但我越来越觉得，也许大家都没搞明白到底发生了什么。"

---

## 快速选择指南

遇到选题时问自己：

- 这件事有**感官体验**？→ 产品体验型
- 这件事有**新闻事件**？→ 热点复盘型
- 这件事涉及**某个人**？→ 人物故事型
- 这件事有**方法论/工具**？→ 方法论型
- 这件事有**争议/不同声音**？→ 观点对冲型
- 以上都不是？→ 可能是方法论型的变体
