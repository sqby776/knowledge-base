# 分享一个我原创的小工具：让你的 Agent 从此搜索不花钱

作者：段诗闻

## 搜索之痛：Agent 的三道坎

在實際使用中，Agent 的搜索能力面临三个核心问题。

### 第一道坎：JavaScript 的"隐形墙"

现代搜索引擎的页面，大量内容是通过 JavaScript 动态渲染的。你用传统 HTTP 请求拿到的 HTML，可能只是一个空壳——真正的搜索结果还没加载出来。

举个例子：Google 搜索引擎页面的核心内容，是在浏览器执行 JavaScript 之后才动态生成的。直接用 HTTP 请求拿到的 HTML，里面可能连一条搜索结果都没有。

这不是 Google 故意刁难，而是现代 Web 的常态——SPA（单页应用）、React、Vue、动态加载……越来越多的网站"必须执行 JavaScript 才能看到内容"。

### 第二道坎：反爬机制的围剿

搜索引擎不是慈善机构。它们靠广告赚钱，不希望被程序批量抓取结果。所以：
- 频繁请求 → IP 封禁
- 检测到自动化 → CAPTCHA 人机验证
- User-Agent 异常 → 返回阉割版页面

### 第三道坎：多引擎的"方言"问题

不同搜索引擎的页面结构完全不同。Google 用 h3 + a 的语义结构，Bing 用 #b_results 容器，百度用 data-log 属性存储真实 URL……每个引擎都有自己的"方言"。

## 我的解法：JS 双路渲染 + 多引擎架构

作者做了一个开源的 MCP 搜索工具：**search-engine-mcp**。

### 核心创新：JS 双路渲染

- **路径一：浏览器模式（Playwright）** — Google、Bing、百度。能拿到 HTTP 拿不到的内容，绕过绝大多数反爬检测，CAPTCHA 用户手动点一下就行。
- **路径二：轻量 HTTP（httpx + selectolax）** — DuckDuckGo 和 Yahoo。1-3 秒返回结果，不占用系统资源，适合高频查询。

### Bing 和百度的"双保险"

浏览器模式为主，HTTP 为备。如果浏览器模式因网络波动、页面加载超时等原因失败，系统会自动切换到 HTTP 请求模式（百度甚至会切换到移动端入口）。

### 五大引擎，按需切换

- 查英文技术文档 → Google（浏览器模式，结果最全）
- 查中文内容 → Bing 或百度
- 快速简单查询 → DuckDuckGo 或 Yahoo（轻量 HTTP，1-3 秒）

### 结构化输出

搜索完成后返回统一格式：

```
标题：Python 基础教程 | 菜鸟教程
链接：https://www.runoob.com/python/python-tutorial.html
摘要：本教程适合想从零开始学习 Python 编程语言的开发人员……
```

### 实战价值

1. **信息实时性** — 获取最新行业报告、竞品动态、实时天气和股价
2. **事实验证** — 降低幻觉率，在医疗、法律、金融场景中尤为关键
3. **深度研究** — "搜索 → 阅读 → 分析 → 总结"的完整工作流
4. **多源对比** — 同时查多个引擎，得到更全面、更可靠的答案

## 技术之外的思考

1. **JavaScript 渲染是搜索工具的分水岭** — 2026 年的互联网，JS 动态渲染已经无处不在
2. **免费方案往往比付费 API 更好用** — 直接浏览器搜索，结果最全、最实时，而且完全免费
3. **失败处理比成功路径更重要** — 双路渲染、超时处理、队列管理——这些"不性感"的设计，才是稳定性的基石
