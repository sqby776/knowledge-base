# 难以想象，skill优化skill——达尔文2.0来了

作者：智枭 | 智枭观察AI | 2026年6月3日

## 背景

Skill 是什么？把重复性的工作流程写成 SKILL.md 文件，以后遇到同样场景直接加载。

杨芳贤手动优化了38轮skill之后，决定不干了。设计了一套让skill**自己进化**的系统。

## 核心机制：棘轮

灵感来自 Karpathy 的 autoresearch（7.1万Star的开源项目）。

autoresearch 做的事情是：AI自动改训练代码，loss下降就保留，没降就回滚。达尔文把这个逻辑搬到了skill优化上。

流程四步：

1. **打分** — 按9维度标准给当前skill评分
2. **找弱点** — 每轮只改分数最低的那个维度
3. **改完实测** — 拿测试prompt跑一遍
4. **分数涨了保留，没涨就回滚**

就像一个只能往前转不能倒转的棘轮。不需要每一步都对，只需要走错的那步不留痕迹。

## 9维度评分体系（2.0版）

1.0是8维，2.0吸收了微软的两篇论文，扩展到了9维：

| 维度 | 分值 | 查什么 |
|------|------|--------|
| Frontmatter质量 | 8分 | 名称规范、描述包含触发词 |
| 工作流清晰度 | 15分 | 步骤明确可执行、有序号、有输入输出 |
| 边界条件/失败模式 | 10分 | 出错了走哪条分支、fallback路径 |
| 检查点设计 | 7分 | 关键决策前有 `/STOP` 强制暂停 |
| 指令具体性 | 15分 | 禁止"建议""可以""视情况而定"等软化词 |
| 资源整合度 | 5分 | references/scripts路径是否可达 |
| 架构合理性 | 15分 | 层次清晰、不冗余不遗漏 |
| 高风险黑名单 ⭐新增 | — | 独立章节列出"绝对不要做什么" |
| 实测表现 | 25分 | 拿测试prompt跑，看输出质量 |

实测表现权重最高——一个结构满分但跑出来一坨的skill，远不如一个写得粗糙但好用的。

2.0最重要的升级：每个评委打分的**准确率从46.4%提升到73.8%**。怎么做到的？失败模式编码 + 可执行具体性 + 高风险黑名单，三个维度同时改进。

## 真实案例

### huashu-slides
5轮优化，从"能用但随时可能翻车"到"可靠到可以去泡咖啡"。

### steve-jobs-perspective
**一轮涨了30分**——从64分直接跳到94分。

### 批量优化
7个perspective skill经过5轮批量优化，从"能用"到"风格稳定、不会漂移"。

### 最震撼的：达尔文优化达尔文
让达尔文分析自己的 SKILL.md。

发现三处违规：
1. 文档描述写"8维评分标准"，正文已经是9维了（前后矛盾）
2. 检查点只用粗体，没有 `/STOP` 标记
3. 自己的文档搜出四处软化措辞

修完后：**86分 → 92.7分**。

一个会进化的skill，改进了"如何写出会进化的skill"这件事。

## 女娲 + 达尔文：从造到磨的闭环

女娲skill负责造——输入一个人名，输出一个可运行的思维框架skill。

达尔文skill负责磨——输入一个skill，输出优化后的版本。

女娲生成skill之后，不会直接交给你。它会自动触发一个 Phase 5 双Agent精炼：Agent A用达尔文的8维度评估体系打分，Agent B用 skill-creator 视角做触发条件评审。两个Agent并行跑完，综合报告，应用改进，才交付。

这意味着女娲生成的每一个skill，**出厂就经过了一轮进化**。

而且达尔文在批量优化中发现的共性问题（比如边界条件缺失、frontmatter太短、引用路径不存在），会反哺回女娲的生成流程中。

## 五个反模式（避坑指南）

1. **同一个AI又改又评** — 写skill的和评分的必须是不同Agent
2. **用 git reset --hard 当回滚** — 应该用 git revert，保留历史
3. **一轮内改多个维度** — 每轮只改最低维度，改多了没法归因
4. **跳过测试直接评分** — 拿prompt跑一遍才算数
5. **为凑分往文档塞冗余** — 质量涨了但skill变臃肿，不可取

## 怎么装

GitHub：https://github.com/alchaincyf/darwin-skill（MIT开源，2.0版）

在你用的小龙虾里说一句：
- `「跑达尔文优化所有skills」` — 批量优化
- `「跑达尔文优化某个skill」` — 单点优化

一轮（基线评估+一轮优化）大约 15-30 分钟。主要耗时在等评委Agent返回。

## 核心体会

达尔文的价值，不是帮你涨那15分。

而是把你的注意力从"自己审自己"转移到"让独立评委审"，并把整个流程做成**可重复、可回滚、有人工卡口**的工程。

以前是"你把流程变成skill，然后去做更有趣的事"。现在连"让skill变得更好"这件事本身，也交给一个skill来做。
